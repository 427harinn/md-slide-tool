# PROJECT_RULES

このファイルは、CodexがこのリポジトリでAI駆動開発を進める際の共通ルールを定義します。

## 基本方針

- 変更は`.ai/MILESTONE.md`と`.ai/TASKS.md`に記載された範囲へ限定する。
- ユーザーが確定していない仕様を、推測で確定しない。
- 既存のCLI、テンプレート出力、レンダリング処理、依存関係、CI、Dev Container、VS Code設定を不用意に変更しない。
- 指示範囲外の全面的なリファクタリングを行わない。
- PPTX、PDF、画像などの生成物やバイナリは、タスク上必要な場合だけ変更する。
- 有料APIや有料サービスを勝手に導入しない。

## 自動進行

- 作業開始前に`PROJECT_CONTEXT.md`、`MILESTONE.md`、`TASKS.md`を確認する。
- `TASKS.md`を上から順番に実行する。
- 停止条件に該当しない限り、小タスクごとの承認を求めない。
- 各タスク後に以下だけを確認する。
  - 変更差分
  - 関連テスト
  - 簡易セルフレビュー
- 問題がなければ次のタスクへ進む。
- 詳細な途中報告は作成せず、マイルストーン完了時にまとめて報告する。
- 全タスク完了後に、全体テスト、最終セルフレビュー、PR作成、完了レポート作成まで行う。
- 自動修正を無制限に繰り返さない。軽微な問題は同じ作業内で修正し、解決しない場合は停止条件に従う。
- 必要以上にリポジトリ全体を繰り返し探索しない。

## 自動判断してよい内容

既存コードとプロジェクトの慣例に従う範囲で、以下は自動判断してよい。

- 軽微な型エラーやLintエラーの修正
- 必要なテストケースやfixtureの追加
- 既存設計に沿った命名やファイル配置
- 既存コンポーネントや共通処理の再利用
- 軽微なエラー処理の追加
- テストセレクターの修正
- 必要最小限のリファクタリング
- 変更内容に対応する軽微なドキュメント更新

## 停止条件

以下の場合だけ作業を停止し、人間の判断を求める。

- 仕様が矛盾している。
- 要件を満たすために対象外機能が必要になる。
- DBの破壊的変更やデータ削除が必要になる。
- 認証方式や権限設計を大きく変更する必要がある。
- 新しい有料サービスや有料APIが必要になる。
- 依存関係のメジャーバージョン更新が必須になる。
- 公開APIや既存データ形式の互換性を壊す必要がある。
- 本番秘密情報がなければ進められない。
- セキュリティ上の重大な判断が必要になる。
- 指定回数修正してもテストが解決しない。
- 変更範囲がマイルストーンを大幅に超える。
- ユーザー体験や確定仕様を大きく変える必要がある。

外部ツール不足により一部の検証ができない場合は、実装可能な範囲と代替検証を先に確認する。安全に実装できる場合は作業を継続し、最終報告に未検証事項を明記する。

停止時は以下を簡潔に報告する。

- 調査結果
- 停止理由
- 判断が必要な点
- 選択肢
- 推奨案

## セルフレビュー

各タスク後とマイルストーン完了時に、変更内容に応じて以下を確認する。

- タスクの完了条件を満たしているか。
- 依頼範囲外の変更がないか。
- 既存機能を壊す可能性がないか。
- 不要な依存関係や設定変更がないか。
- 正常系と必要な異常系が確認されているか。
- エラーメッセージが利用者に理解できるか。
- ドキュメントが実装と矛盾していないか。
- 確認済み事実と未確認事項を区別しているか。

詳細は`.ai/REVIEW_CHECKLIST.md`を参照する。

## GUI確認

GUI、VS Code Webview、プレビュー表示などを変更する場合は、既存の検証環境を利用する。

- 実際のユーザー操作と結果をassertionで確認する。
- 機能に応じて初期状態、処理中、成功、エラー、操作後の反映状態を確認する。
- 読み込みや画面更新の完了後にスクリーンショットを保存する。
- 失敗時は、可能な範囲で以下を保存する。
  - 失敗時スクリーンショット
  - Trace
  - コンソールログ
  - ネットワークまたはプロセスのエラー
  - テスト結果
- 秘密情報、パスワード、トークンを画像やログへ残さない。
- GUI/E2E環境が存在しない場合は勝手に導入せず、`MILESTONE.md`または`TASKS.md`で導入が明示されている場合だけ追加する。

## PR作成と完了報告

小タスクごとにPRを作成しない。

1つのユーザー操作または機能群が完了し、独立してレビューできる段階でPRを作成する。

PR本文には以下を含める。

- 変更の目的
- 完成した機能
- 完了したタスク
- 主な変更ファイルと役割
- 完了条件に対する結果
- 実行したテストと結果
- GUI確認結果とスクリーンショットの保存場所
- セルフレビューで発見・修正した問題
- 未解決事項
- 既知の制限
- 必要な手動設定

## Codex利用上限の節約

- 仕様整理済みの`MILESTONE.md`と`TASKS.md`を実装の基準にする。
- 共通ルールを作業報告へ全文再掲しない。
- 小タスクごとの長い報告を作成しない。
- 同じ情報を繰り返し探索しない。
- `node_modules`、生成物、大きなバイナリを不用意に読まない。
- 調査結果は必要に応じて`PROJECT_CONTEXT.md`へ反映し、再調査を減らす。
- テスト、Lint、型チェック、GUI操作は通常の実行ツールで確認する。
