# PROJECT_RULES

このファイルは、Codex がこのリポジトリで AI 駆動開発を進める際の詳細ルールを定義する。

## 基本方針

- 変更は依頼された範囲に限定する。
- 既存の CLI 挙動、テンプレート出力、レンダリング処理、依存関係、CI、Dev Container、VS Code 設定を不用意に変更しない。
- 推測で仕様を確定しない。未確定の要件は `.ai/MILESTONE.md` または `.ai/TASKS.md` の未確定欄に残す。
- 生成物、サンプル成果物、PPTX/PDF/画像などのバイナリを変更する場合は、明示依頼があるときだけ行う。

## 自動進行

- 調査は、依頼されたファイルとその直接依存に限定する。
- 既存機能に影響する変更では、README、CLI、scripts、tests、CI の関係を最小限確認する。
- コード変更時は、小さい差分に分け、変更理由を説明できる状態にする。
- コマンド実行前に、成果物や設定を書き換える可能性があるか確認する。

## 停止条件

以下の場合は作業を止め、状況を報告する。

- 依頼範囲を超える機能実装、依存追加、設定変更が必要になった場合。
- 既存コードや成果物を破壊する可能性がある場合。
- 仕様が複数解釈でき、実装判断が必要な場合。
- 外部ツール、Quarto、Python、Docker、GUI 環境などが不足して検証できない場合。

## セルフレビュー

変更後に以下を確認する。

- 依頼範囲外のファイルを変更していないか。
- `package.json`、`package-lock.json`、既存設定、既存コードを不要に変更していないか。
- ドキュメントの記述が、確認済み事実と未確認事項を区別しているか。
- 実行コマンド、テスト有無、E2E 有無を誤って断定していないか。

## GUI確認

- Web アプリ、VS Code Webview、GUI プレビューなど表示に影響する変更をした場合は、可能な範囲でスクリーンショットを取得する。
- 現在確認できる範囲では、このリポジトリは主に `slidegen` CLI として動作している。GUI/E2E を勝手に導入しない。

## PR報告

- PR を作成する場合は、変更の目的、変更ファイル、検証結果、未確認事項を簡潔に書く。
- 依存関係や既存設定を変更していない場合は、その旨を明記する。
- GUI/E2E 環境が未整備の場合は、未整備として報告する。

## Codex利用上限節約

- `rg --files`、`find`、対象ファイルの `sed`/`cat` で必要範囲だけ確認する。
- 大きなファイルや生成物、バイナリ、`node_modules`、成果物を不用意に読まない。
- 同じ情報を繰り返し探索しない。
- 調査結果は `.ai/PROJECT_CONTEXT.md` に集約し、次回以降の再調査を減らす。
