# PPTX image placement

## 概要

`slidegen render` で PPTX 向け QMD をレンダリングするとき、md-slide-tool は QMD 内の一部の Markdown 画像を前処理で抽出し、Quarto のレンダリング後に PPTX へ画像を後付け配置します。

この仕組みにより、Quarto の通常の画像レイアウトではなく、md-slide-tool 側の後処理によってスライド内の空き領域を推定し、画像とキャプションを自動配置します。

大まかな流れは次のとおりです。

1. 入力 QMD から対象画像行を抽出する。
2. 対象画像行を除いた一時 QMD を作る。
3. 抽出した画像情報を `.images.json` に保存する。
4. 一時 QMD を Quarto で PPTX にレンダリングする。
5. `.images.json` をもとに、生成済み PPTX へ画像を追加する。

## 対象となる画像記法

### 対象

次のように、1 行全体が Markdown 画像だけで構成されている行が対象です。

- `![caption](path)`
- `![caption](path){place=right}`

例:

```md
## スライドタイトル

本文

![キャプション](img/example.png)
```

画像の alt テキストは、PPTX 後処理で画像下に追加されるキャプションとして使われます。

### 対象外

次のような画像は、現状の自動配置対象にはなりません。

- 文中画像
- HTML `<img>`
- 参照形式画像
- `##` 見出しより前の画像

対象外の例:

```md
本文中に ![画像](img/example.png) を置く
```

```md
<img src="img/example.png">
```

```md
![画像][example]

[example]: img/example.png
```

`##` 見出しより前に画像を書いた場合、その画像を紐づけるスライドがまだないため、自動配置対象にはなりません。

## スライドとの対応付け

QMD の前処理では、`##` 見出し単位でスライドを扱います。画像は、直前の `##` 見出しのスライドに紐づきます。

```md
## 1枚目

![1枚目の画像](img/slide1.png)

## 2枚目

![2枚目の画像](img/slide2.png)
```

この例では、`img/slide1.png` は `1枚目` スライド、`img/slide2.png` は `2枚目` スライドに紐づきます。

PPTX 後処理では、`.images.json` に保存されたスライド番号をそのまま使って配置先を決めるのではなく、PPTX 内のスライドタイトルと `.images.json` 側のタイトルを比較し、タイトルが一致するスライドを探します。

そのため、同名タイトルのスライドが複数ある場合は注意してください。現状では、最初にタイトルが一致した PPTX スライドに画像が配置される可能性があります。意図しないスライドに画像が入ることを避けるため、画像を使うスライドではタイトルを重複させないことを推奨します。

また、テンプレートや Quarto のレンダリング結果によって PPTX 側のタイトル文字列が変わると、タイトル一致に失敗し、画像が追加されない可能性があります。

## `.images.json` の形式

前処理では、抽出した画像情報を `.images.json` に保存します。通常、このファイルはレンダリング中に一時的に作成され、後処理後に削除されます。

例:

```json
[
  {
    "slide_index": 0,
    "title": "スライドタイトル",
    "images": [
      {
        "path": "img/example.png",
        "caption": "キャプション",
        "place": "right"
      }
    ]
  }
]
```

各フィールドの意味は次のとおりです。

| フィールド | 意味 |
| --- | --- |
| `slide_index` | QMD 内で検出された `##` 見出しの順番です。0 始まりです。 |
| `title` | `##` 見出しのテキストです。PPTX 後処理では、このタイトルを使って配置先スライドを探します。 |
| `images` | そのスライドに紐づく画像の配列です。 |
| `images[].path` | Markdown 画像の `(...)` に書かれた画像パスです。通常は QMD と同じディレクトリを基準に解決されます。 |
| `images[].caption` | Markdown 画像の alt テキストです。PPTX では画像下のキャプションとして使われます。 |
| `images[].place` | `{place=...}` 属性の値です。現状では保存のみで、配置制御には使われません。 |

## 配置アルゴリズム

PPTX 後処理では、既存のタイトル領域・本文領域を推定し、それらと重なりにくい場所へ画像を配置しようとします。

利用者向けに見ると、処理は次のようなヒューリスティックです。

- 既存のタイトル領域・本文領域を推定する。
- 右側、右下、下側の候補領域を評価する。
- 各候補領域に画像を置いた場合の画像サイズを計算する。
- 画像を最も大きく置ける候補を選ぶ。

これは完全なレイアウトエンジンではありません。スライド内のすべての図形、表、コードブロック、レンダリング済み画像、Mermaid 図などを厳密に理解して配置するものではなく、既存のテキスト領域を中心に推定するヒューリスティックです。

### 1枚画像の場合

1 枚画像の場合は、主に次の候補領域が評価されます。

- `right`: 既存コンテンツの右側
- `bottom_right`: 既存コンテンツの右下
- `bottom`: 既存コンテンツの下側

`bottom_right` は 1 枚画像のときだけ候補になります。候補領域内に画像をアスペクト比維持で収め、キャプションがある場合は画像下にキャプション領域を確保します。

### 複数画像の場合

複数画像の場合は、主に次のどちらかになります。

- `right` の縦積み
- `bottom` の横並び

縦積みでは、右側の候補領域を画像枚数に応じて上下に分割します。横並びでは、下側の候補領域を画像枚数に応じて左右に分割します。

各画像は、割り当てられた領域に収まるようにアスペクト比を維持して縮小されます。現状では、元画像サイズより大きく拡大することはありません。

### キャプション

Markdown 画像の alt テキストは、PPTX 上で画像下のキャプションとして追加されます。

```md
![売上推移グラフ](img/sales-chart.png)
```

この例では、`売上推移グラフ` がキャプションとして使われます。

alt テキストが空の場合、キャプションは追加されません。

### off-slide fallback

候補領域が見つからない場合、画像はスライド右外側の表示領域外に置かれる可能性があります。これは、配置できなかった画像を PPTX ファイル内に残すための fallback です。

ただし、通常のスライド表示領域の外に置かれるため、利用者からは「画像が表示されていない」ように見えることがあります。

画像が表示されない場合は、次を確認してください。

- 画像が単独行の Markdown 画像になっているか。
- 画像パスが正しいか。
- 画像を書いた位置が `##` 見出しより後か。
- PPTX 側のタイトルと QMD の `##` 見出しが一致しているか。
- スライド内の本文量が多すぎて、配置候補がなくなっていないか。

## `place` 属性の現状

`place` 属性は、現状では前処理で抽出され、`.images.json` に保存されます。

```md
![画像](img/example.png){place=right}
```

ただし、現在の PPTX 後処理では `place` の値を配置制御に使っていません。そのため、`{place=right}` のように書いても、現時点では配置指定としては機能しません。

`place` 属性による明示的な配置制御は、将来の拡張候補です。現状の仕様としては、`place` は保存されるだけで、実際の配置は自動配置アルゴリズムに任されます。

## よくある問題

### 画像が出ない

考えられる原因は次のとおりです。

- 単独行ではない。
- 画像パスが間違っている。
- `##` 見出しより前に画像を書いている。
- PPTX 側のタイトルと一致しない。
- off-slide fallback になっている。

まず、画像を次のような単独行にしてください。

```md
![キャプション](img/example.png)
```

また、画像ファイルが QMD から見て正しい相対パスにあることを確認してください。

### 意図したスライドに入らない

同じタイトルのスライドが複数あると、PPTX 後処理で意図しないスライドに画像が入る可能性があります。

画像を使うスライドでは、`##` 見出しのタイトルを重複させないことを推奨します。

### 画像が小さい

現状では、画像は候補領域に収まるように縮小されますが、元画像サイズより大きく拡大されません。そのため、元画像が小さい場合は、スライド上でも小さいままになる可能性があります。

大きく表示したい画像は、元画像の解像度やサイズを十分に大きくしておくことを推奨します。

## 推奨される書き方

1 枚画像の例:

```md
## 売上推移

- 2025年は前年比120%
- 第4四半期に伸長

![売上推移グラフ](img/sales-chart.png)
```

複数画像の例:

```md
## A案とB案の比較

- A案は導入が簡単
- B案は拡張性が高い

![A案の構成図](img/plan-a.png)
![B案の構成図](img/plan-b.png)
```

書き方のポイント:

- 画像は単独行にする。
- 画像は紐づけたい `##` 見出しの後に書く。
- alt テキストには、画像下に表示したい短いキャプションを書く。
- 画像を使うスライドでは、`##` 見出しのタイトルを重複させない。
- `{place=...}` は現時点では配置指定として機能しないため、配置制御を期待して使わない。

## 将来予定

次の機能は将来の拡張候補です。現時点では実装済みではありません。

- `place` 属性による明示配置
- preview 機能
- 配置結果を事前確認するための補助機能
- より詳細なレイアウト制御
